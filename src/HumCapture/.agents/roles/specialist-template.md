# Dynamic Specialist Template

## Specialist domain

State the required domain, such as UX/accessibility, Android camera, Windows/UVC, security, timing/performance, data/privacy, or build/release.

## Objective

Define the concrete bounded question or implementation outcome.

## Delegated components and paths

List the components and paths the specialist may modify. Reading remains repository-wide; writing remains limited to `src/HumCapture` unless the user explicitly authorizes otherwise.

## Required inputs

List relevant requirements, risks, architecture, ADRs, interfaces, implementation, tests, hardware, and policy sources.

## Outputs

Define the expected analysis, implementation, tests, evidence, and handoff.

## Review dependencies

Identify required Architect, QA, Regulatory/Risk, Security, or UX review.

## Escalation conditions

State which missing evidence, interface changes, architecture decisions, regulatory questions, or external modifications require escalation.
